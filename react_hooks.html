Understand how function components work with state, effects, refs and reusable behavior — through small examples that are easy to run and explain in class.

1. What are Hooks?

Hooks are React functions that let function components use capabilities that historically belonged mainly to class components.

State

Store data that can change and update the UI.

Effects

Perform extra work after rendering, such as timers or API requests.

Refs

Persist a value between renders or access a DOM element through current.

Reusable behavior

Hooks also support context, reducers and memoization, and make custom Hooks easier to create.

Simple idea: Hooks let function components “remember, react, and reach outside the normal UI” without needing class syntax.

2. useState

useState returns an array containing the current state value and a setter function.

import { useState } from "react";

export default function App() {
  const [count, setCount] = useState(0);

  return (
    <>
      <h1>{count}</h1>
      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </>
  );
}

3. Updater Function

The source recommends an updater function when the next state depends on the previous state, especially when several updates may be batched.

function increase() {
  setCount(previousCount => previousCount + 1);
}

Why is it useful?

May be unreliable for “add 2”

setCount(count + 1);
setCount(count + 1);

Both updates may use the same count value from that render.

Functional updater

setCount(previousCount => previousCount + 1);
setCount(previousCount => previousCount + 1);

Each updater receives the latest previous value for the update.

4. Objects and Arrays in State

For objects and arrays, the setter replaces the stored value. Preserve existing properties when updating an object with the spread operator.

const [student, setStudent] = useState({
  name: "Avinash",
  age: 25
});

function changeName() {
  setStudent({
    ...student,
    name: "Rahul"

5. useEffect and Side Effects

useEffect is used when React should perform extra work after rendering the screen / UI.

Browser title

Change the browser tab title.

Timer

Start a timer and clean it up when needed.

API request

Get data from an API after rendering.

External connection

Add a browser event listener or connect to an external service.

Remember the two questions: “What should I do?” and “When should I do it?”
useEffect(() => {
  // work to do

  return () => {
    // cleanup work
  };
}, [dependencies]);

Example: Changing the browser title

import { useEffect, useState } from 'react';

export default function App() {
  const [topic, setTopic] = useState('Components');

  useEffect(() => {
    document.title = `Study: ${topic}`;
  }, [topic]);

  return (
    <>
      <p>Current topic: {topic}</p>
      <button onClick={() => setTopic('Hooks')}>
        Change Topic
      </button>
    </>
  );
}

Why useEffect here? The paragraph is part of React’s UI, but document.title = ... changes something outside that UI.

6. Dependency Array

The second part of useEffect is the dependency array. It tells React when the effect should run again.

FormMeaning in the source
useEffect(() => { ... })Runs after every render.
useEffect(() => { ... }, [])Runs after the component appears; cleanup runs on unmount.
useEffect(() => { ... }, [topic])Runs when topic changes.

Classroom shortcut: Ask “When should this extra work happen?” Then choose the dependency form that matches that answer.

7. useEffect Timer

The source uses a timer to demonstrate an effect with setup and cleanup.

function Clock() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setSeconds(s => s + 1);
    }, 1000);

    return () => clearInterval(id);
  }, []);

  return <p>Seconds: {seconds}</p>;
}

0

The conceptual equivalent in React uses setInterval inside useEffect and clearInterval during cleanup.

Cleanup matters: When a component using the timer is removed, cleanup prevents the old interval from continuing to run.

8. useEffect with API Calls

The source demonstrates loading temperature data from an API with fetch(), storing the result with useState, and showing “Loading...” until the result arrives.

import { useEffect, useState } from 'react';

export default function App() {
  const [temperature, setTemperature] = useState(null);

  useEffect(() => {
    fetch(
      'https://api.open-meteo.com/v1/forecast?latitude=18.7762&longitude=84.095&current=rain,temperature_2m&forecast_days=1'
    )
      .then(response => response.json())
      .then(data => {
        setTemperature(data.current.temperature_2m);
      });
  }, []);

  return (
    <>
      <h1>Current Temperature</h1>
      <p>
        {temperature === null ? 'Loading...' : `${temperature} °C`}
      </p>
    </>
  );
}

9. useState vs useEffect

useStateuseEffect
Stores dataPerforms side effects
Example: nameExample: API request
Example: countExample: timer
State changes can cause a re-renderRuns after rendering
setState() changes stateEffect synchronizes with the outside world
Easy distinction: useState answers “What data should this component remember?” useEffect answers “What extra work should happen after rendering?”

10. useRef

useRef stores a value that persists between renders without causing a re-render when that value changes. It can also directly access a DOM element through its current property.

import { useRef } from "react";

export default function App() {
  const inputRef = useRef(null);

  function focusInput() {
    inputRef.current.focus();
  }

  return (
    <>
      <input ref={inputRef} placeholder="Enter your name" />
      <button onClick={focusInput}>
        Focus Input
      </button>
    </>
  );
}

11. Video / Media Controls with useRef

The source uses a ref to call media methods such as play() and pause().

const videoRef = useRef(null);

function playVideo() {
  videoRef.current.play();
}

function pauseVideo() {
  videoRef.current.pause();
}
