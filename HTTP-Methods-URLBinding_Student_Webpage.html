1 • Big picture

What are HTTP methods?

HTTP methods tell the server what the client wants to do with data. In Express, each method has a matching function such as app.get() or app.post(). fileciteturn1file0L4-L7

ELI10: Think of an HTTP method as an instruction on a delivery slip: GET means “show me,” POST means “here is new information,” PUT means “replace it,” PATCH means “change this part,” and DELETE means “remove it.”

Route examples

app.get("/users", (req, res) => {
  res.send("List of users");
});

app.post("/users", (req, res) => {
  res.send("New user created");
});

app.put("/users/:id", (req, res) => {
  res.send(`User ${req.params.id} fully replaced`);
});

app.patch("/users/:id", (req, res) => {
  res.send(`User ${req.params.id} partially updated`);
});

app.delete("/users/:id", (req, res) => {
  res.send(`User ${req.params.id} deleted`);
});

4 • More HTTP methods

HEAD and OPTIONS

HEAD

HEAD is like GET, but the server returns response headers rather than the actual response body. It can provide information such as content type, file size, or last-modified time. fileciteturn1file0L92-L103

app.head("/profile", (req, res) => {
  res.set("Content-Type", "application/json");
  res.set("Last-Modified", "Sun, 23 Aug 2026 10:00:00 GMT");
  res.status(200).end();
});
Remember: “GET gives the content; HEAD gives information about the content.”

OPTIONS

OPTIONS asks which communication options or HTTP methods are available for a URL. A common use is a browser's CORS preflight check before a cross-origin request. fileciteturn1file0L104-L115

app.options("/users", (req, res) => {
  res.set("Allow", "GET, POST, OPTIONS");
  res.status(204).end();
});

The source notes that cors middleware commonly handles browser CORS-related OPTIONS requests automatically in Express applications. fileciteturn1file0L113-L115

Static routes are fixed. Dynamic routes let you place parameters in the URL so the server can process different values. fileciteturn1file0L120-L125

6 • Route parameters

Multiple parameters in a URL

Express can capture more than one URL parameter. The source uses /things/:name/:id. fileciteturn1file0L139-L149

var express = require('express');
var app = express();

app.get('/things/:name/:id', function(req, res) {
  res.send('id: ' + req.params.id + ' and name: ' +
           req.params.name);
});

app.listen(3000);

7 • Pattern matching

Restricting route parameters with a pattern

You can use a regular expression to restrict what a dynamic parameter is allowed to match. The source example requires the ID to be exactly five digits. fileciteturn1file0L158-L170

var express = require('express');
var app = express();

app.get('/things/:id([0-9]{5})', function(req, res){
  res.send('id: ' + req.params.id);
});

app.listen(3000);
Pattern explained: [0-9] means a digit, and {5} means five occurrences. So the route accepts a 5-digit ID.

8 • Invalid URLs

Handling a route that does not match

If none of the defined routes match a request, the source notes that Express can respond with a message such as Cannot GET <your-request-route>. It then demonstrates a final route that can return a custom invalid-URL message. fileciteturn1file0L169-L180

var express = require('express');
var app = express();

// Other routes here

app.get('*', function(req, res){
  res.send('Sorry, this is an invalid URL.');
});

app.listen(3000);
Important: Put this catch-all route after all your other routes. Express matches routes from the start to the end of the file, including external routers that you require. fileciteturn1file0L187-L189

Study summary

What you should remember

  • Express provides method-specific route functions such as app.get() and app.post(). fileciteturn1file0L4-L7
  • GET reads, POST creates, PUT replaces, PATCH updates part, and DELETE removes.
  • HEAD returns headers/metadata without the response body; OPTIONS can tell the client which methods/options are available. fileciteturn1file0L92-L115
  • Dynamic routes use placeholders such as :id and :name. Their values are available through req.params. fileciteturn1file0L125-L136
  • Route patterns can restrict which parameter values are accepted. fileciteturn1file0L158-L172
  • A catch-all invalid-URL route should come after the other routes. fileciteturn1file0L187-L189
